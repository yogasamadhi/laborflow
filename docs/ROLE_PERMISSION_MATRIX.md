# LaborFlow 角色与权限矩阵

## 1. 用途与判定原则

本矩阵冻结当前正式上线范围内的角色、菜单、接口能力和数据范围。服务端鉴权是最终
判定依据；Web 与小程序只负责隐藏不适用的入口和降低误操作，不能替代接口校验。

默认角色来自 `V2__seed_data.sql`：`ADMIN`、`BOSS`、`FINANCE`、`MANAGER`、
`EMPLOYEE`。代码中不存在独立的 `PROJECT_MANAGER`、`PM` 或“项目人员”角色。
“项目人员”是业务身份：任意已登录账号（通常为 `EMPLOYEE`）通过有效的项目成员关系
获得指定项目的数据范围。

所有 `/api/**` 接口默认要求登录；只有登录、注册和微信会话交换接口允许匿名访问。
接口返回的 401/403 与业务层的“无权访问该项目”错误都必须在后续权限回归中覆盖。

## 2. 角色能力矩阵

| 能力域 | ADMIN | BOSS | FINANCE | MANAGER | EMPLOYEE |
| --- | --- | --- | --- | --- | --- |
| 系统用户、角色、操作日志、微信绑定管理 | 完整 | 无 | 无 | 无 | 无 |
| 部门、岗位、员工管理 | 完整 | 完整 | 无 | 完整 | 无 |
| 工资项、工资档案、月度工资、导出与统计 | 完整 | 完整 | 完整 | 无 | 仅本人工资历史、工资条确认/反馈 |
| 月度工资审核/驳回 | 完整 | 完整 | 无 | 无 | 无 |
| 考勤、扣款、绩效方案/评分、奖金与薪酬看板 | 完整 | 完整 | 完整 | 完整 | 无 |
| 项目台账、施工段、合同清单、工序、班组、日报确认、签证确认 | 完整 | 完整 | 无 | 完整 | 仅已授权项目的本人日报/签证填报与查看 |
| 机械设备、机械台班、材料记录、项目资料归档读取与维护 | 完整 | 完整 | 无 | 完整 | 无 |
| 班组结算、项目回款、成本、风险、经营看板 | 完整 | 完整 | 完整 | 完整 | 无 |
| 私有文件下载 | 依业务归属授权 | 依业务归属授权 | 依业务归属授权 | 依业务归属授权 | 仅本人或已授权项目附件 |

“完整”仅表示该能力域的业务角色权限，不绕过状态机、数据校验、附件归属或审计要求。

## 3. 数据范围与项目人员规则

| 身份 | 项目范围 | 日报与签证范围 | 工资范围 |
| --- | --- | --- | --- |
| ADMIN/BOSS/MANAGER | 依据系统项目管理角色访问全部项目 | 可查看、维护和确认项目业务数据 | 依工资管理角色查看全量 |
| FINANCE | 全部项目的财务和经营数据 | 非本人创建的日报/签证不能编辑、提交或确认 | 可查看和处理全量工资，但不能审核/驳回月度工资 |
| EMPLOYEE + 有效项目成员关系 | 仅关联项目 | 仅本人创建的日报/签证；创建或修改时目标项目必须已授权 | 仅账号绑定员工的工资历史、工资条、确认与反馈 |
| EMPLOYEE + 无项目成员关系 | 无项目数据范围 | 不可向任意项目创建、改挂日报或签证 | 同上，前提是账号已绑定员工 |

有效项目成员关系的条件是成员记录未删除、状态为 `active`，并且其 `employee_id` 与
当前登录账号关联的员工一致；项目成员不再接受或保存 `user_id`。未关联员工的账号只能
依据系统角色访问，不能被项目成员记录伪装。财务拥有项目财务范围，但不是项目业务管理员；
因此不能代替项目经理编辑或确认日报、签证。

机械设备、机械台班、材料记录和项目资料归档的读取接口同样属于项目业务管理，
`EMPLOYEE` 与 `FINANCE` 直接调用时必须返回 403；菜单隐藏不能替代该接口鉴权。

## 4. Web 管理端菜单

| 菜单组 | 可见角色 | 说明 |
| --- | --- | --- |
| 工作台综合仪表盘 | 所有已登录角色 | 单接口按角色返回能力区域；EMPLOYEE 不返回敏感经营汇总 |
| 员工、部门、岗位 | ADMIN/BOSS/MANAGER | 组织管理 |
| 工资管理 | ADMIN/BOSS/FINANCE | 审核操作仍只限 ADMIN/BOSS |
| 项目台账、施工段、工序、合同、日报、班组、签证、机械、材料、资料 | ADMIN/BOSS/MANAGER | 项目业务管理入口 |
| 班组结算、回款、成本、风险、经营看板 | ADMIN/BOSS/MANAGER/FINANCE | 项目财务与经营入口 |
| 薪酬与绩效 | ADMIN/BOSS/MANAGER/FINANCE | 薪酬输入、绩效方案、绩效评分和奖金入口 |
| 系统管理 | ADMIN | 用户、角色、操作日志和微信绑定 |

Web 路由按同一角色矩阵拦截隐藏页面的直接访问，并显示可返回工作台的拒绝状态；服务端
仍是最终拒绝依据。`L2-22-01` 同时覆盖路由直达、401 登录失效和 403 操作反馈。

## 5. 微信小程序现场端

| 场景 | 可见或可操作角色 | 服务端约束 |
| --- | --- | --- |
| 本人工资、工资条确认与反馈 | 已绑定员工的任意登录角色 | 仅绑定员工自己的工资明细 |
| “现场”页签的日报、签证与附件 | 已授权项目成员；管理角色也可操作 | 服务端详情加载、真实分页；创建和修改都校验目标项目范围与附件状态 |
| 统一审批待办 | ADMIN/BOSS：工资及获授权业务；MANAGER：日报、签证、结算；FINANCE：班组结算 | `/api/todos` 按角色和项目范围返回；详情动作继续执行状态与角色校验 |
| 首页与个人中心 | 所有已登录角色 | 读取失败时遵循接口授权与数据范围 |

## 6. 实现来源与后续回归

- 服务端角色表达式：`server/src/main/java/com/company/labor/security/RoleExpressions.java`。
- 项目数据范围：`ProjectAccessServiceImpl` 的角色范围与项目成员关系。
- 工资本人访问：`SalaryMonthlyController` 与 `StatisticsController` 的员工绑定校验。
- 菜单显示：`web/src/components/layout/AppLayout.tsx`。
- 小程序待办筛选：`miniapp/services/todo.js` 与 `miniapp/utils/auth.js`。

本文件是验收口径，不替代自动化验证。`L2-22-01` 至少应覆盖匿名 401、越权 403、
授权 200、项目范围拒绝、工资本人访问、敏感字段脱敏，以及隐藏菜单后的直接路由访问体验。
