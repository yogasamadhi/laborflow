# LaborFlow 初始化验收清单

## 1. 用途与边界

本清单用于新建或隔离测试数据库完成 Flyway 后的业务初始化验收。它覆盖首次管理员、
默认角色、工资项、工序库、测试账号和微信绑定准备，不包含生产部署、域名、证书、
监控、备份或真实生产密钥开通。

执行时不得把管理员密码、JWT、数据库密码、微信 AppSecret、openid、身份证、银行卡或
真实手机号写进本文件、截图、命令历史或提交记录。每一步记录执行人、时间、环境、
结果和证据位置即可。

## 2. 数据库与首次管理员

| 检查项 | 操作 | 通过标准 |
| --- | --- | --- |
| 空库迁移 | 启动服务并确认 Flyway 执行至当前最新版本 | 迁移无失败；`sys_role`、`sys_user`、`salary_item` 等核心表存在 |
| 首次管理员 | 当不存在启用的 ADMIN 时，仅在启动进程环境中同时设置 `BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD` 后启动服务 | 用户名为 3-64 字符、密码为 12-64 字符；服务创建或恢复一个启用的 ADMIN；日志不含密码 |
| 受控恢复 | 同名账号已存在时，仅允许恢复已有 ADMIN 角色的停用账号 | 同名普通账号不会被提权；已有启用 ADMIN 时 bootstrap 不改动任何账号 |
| 一次性清理 | 用首次管理员成功登录后，从启动环境移除两项 bootstrap 配置并重启服务 | 服务正常启动；管理员仍可登录；不再产生 bootstrap 管理员操作记录 |

若没有启用 ADMIN 且未提供两项 bootstrap 配置，服务拒绝启动是预期保护行为，不应通过
自助注册、修改前端或公开接口绕过。自助注册仅创建 `EMPLOYEE`。

## 3. 默认角色与账号准备

| 角色 | 代码 | 验收动作 |
| --- | --- | --- |
| 超级管理员 | ADMIN | 可管理用户、角色、日志和微信绑定 |
| 老板/负责人 | BOSS | 可审核工资，查看工资与项目经营数据 |
| 财务 | FINANCE | 可管理工资、薪酬输入和项目财务；不可审核工资或确认日报/签证 |
| 项目经理/管理人员 | MANAGER | 可管理组织和项目业务，确认日报/签证；不可查看工资管理入口 |
| 普通员工 | EMPLOYEE | 仅可在绑定后查看本人工资，并在项目成员范围内处理现场业务 |

1. 以 ADMIN 登录后确认以上五个角色均为 `active`，代码与
   [`ROLE_PERMISSION_MATRIX.md`](ROLE_PERMISSION_MATRIX.md) 一致。
2. 创建 BOSS、FINANCE、MANAGER、EMPLOYEE 测试账号，不使用真实个人信息或弱密码。
3. 为需要查看工资或使用小程序的账号绑定测试员工；为现场 EMPLOYEE 建立有效项目成员
   关系。另保留一个未关联项目的 EMPLOYEE 用于越权验收。
4. 以各角色分别登录 Web 和小程序，确认菜单、待办和接口结果符合权限矩阵。

## 4. 工资与组织基线

| 检查项 | 通过标准 |
| --- | --- |
| 部门和岗位 | 至少有两个启用部门和可用岗位，可验证同月分部门核算与直属子部门不归并 |
| 员工 | 每个工资测试部门至少一名在职测试员工已维护直属部门；另备一名无部门员工验证档案启用拒绝 |
| 默认工资项 | 存在基本工资、岗位工资、绩效工资、餐补、交通补贴、通讯补贴、加班费、奖金，以及请假、社保、借支、罚款、其他扣款等默认项；类型和启停状态正确 |
| 工资档案 | 有直属部门的测试员工存在有效工资档案；档案列表可按直属部门分组、筛选和汇总 |
| 薪酬来源 | 可准备非真实的考勤、扣款、绩效或项目奖金来源，用于 UAT 工资来源验证 |

工资项可以按公司规则补充，但不得删除仍被历史工资快照引用的项目。金额、卡号和工资条
截图必须使用脱敏测试数据。

同一测试月份应分别创建两张部门工资表，验证各自生成、审批和发放；不得为无部门员工
创建启用档案，也不得以“未分配部门工资表”绕过组织信息维护。

## 5. 项目与工序基线

1. 创建一个状态为 `in_progress` 的测试项目，并维护项目经理、施工范围和测试备注。
2. 创建至少一个施工段、一个工序、一个合同清单和一个班组；为结算流程配置班组单价。
3. 工序库应使用实际业务可识别名称和单位，至少覆盖 UAT 所需的工程量日报项目；不要把
   未确认的临时工序直接写入正式工序库。
4. 为测试项目创建项目成员关系，确认现场 EMPLOYEE 仅能选择该项目；未关联项目的账号
   创建日报或签证必须失败。
5. 准备一份非敏感测试图片，分别用于日报照片、签证附件和文件授权检查。

## 6. 微信小程序准备

| 检查项 | 操作与通过标准 |
| --- | --- |
| 小程序配置 | 仅在运行环境配置 `WECHAT_MINIAPP_APP_ID`、`WECHAT_MINIAPP_APP_SECRET`；仓库和验收记录中保持为空或脱敏 |
| 登录交换 | 使用测试小程序账号完成微信会话交换和平台登录；失败时不写入伪造绑定 |
| 管理绑定 | ADMIN 在系统微信绑定页面查询、绑定、解绑和停用测试绑定；操作有审计记录 |
| 员工验证 | 已绑定员工可看到本人工资和现场入口；未绑定或停用绑定按预期提示并拒绝受限操作 |

## 7. 初始化完成判定

- 启用 ADMIN 存在且 bootstrap 配置已从运行环境移除。
- 五个默认角色、测试账号、员工绑定、项目成员关系、部门岗位、工资项、工资档案、测试
  项目和工序库均已复核。
- UAT 所需的工资、日报、签证、结算、附件和微信绑定测试数据准备完毕且不含真实敏感
  信息。
- 执行 [`UAT_CHECKLIST.md`](UAT_CHECKLIST.md) 中的至少一条工资和一条现场流程前置检查
  无阻塞；未完成事项记录在 UAT 或缺陷跟踪中。
