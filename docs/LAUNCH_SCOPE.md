# LaborFlow 正式上线范围

## 1. 文档用途与状态

本文件是 LaborFlow 本次正式上线的功能范围单一事实来源。它只冻结产品和验收范围，
不代表所有项目已通过 UAT、迁移、权限或体验验证；这些上线前工作由
[`LOOPMAP2.md`](LOOPMAP2.md) 管理。

本次范围不包含部署与运维工作。生产环境、域名、HTTPS、反向代理、监控、备份恢复、
告警、密钥、对象存储开通等事项不在本文件的完成声明内。

## 2. 本次正式上线的目标用户

| 用户角色 | 本次主要工作 |
| --- | --- |
| 管理员 | 管理系统用户、角色、微信绑定与操作日志 |
| 老板/负责人 | 审核工资，查看工资、项目与经营数据 |
| 财务 | 维护工资档案、生成和发放工资、导出工资数据、管理薪酬输入 |
| 项目经理/管理人员 | 维护项目、工程量、班组、签证、结算、成本和回款 |
| 员工/现场人员 | 通过小程序查看本人工资、填报日报和签证、处理待办 |

角色的精确菜单、接口和数据范围将在 `L2-20-02` 的
`docs/ROLE_PERMISSION_MATRIX.md` 中冻结；本节不替代服务端授权规则。

## 3. 纳入本次正式上线的功能

### 3.1 账号、组织与审计

- Web 登录、JWT 会话、系统用户、角色、操作日志和微信绑定管理。
- 员工、部门、岗位、员工状态、银行卡、紧急联系人和员工备注维护。
- 按既有角色控制菜单、接口和项目数据范围；关键操作保留审计入口。

### 3.2 工资与薪酬

- 工资项和工资档案维护。
- 月度工资创建、生成、明细调整、提交、审核、驳回、单人或批量发放和凭证关联。
- 工资条查看、确认与反馈，工资历史、统计、异常提醒及现有导出入口。
- 考勤、工资扣款、绩效指标、绩效方案与评分、项目奖金池和奖金分配进入工资来源；绩效
  基数、加权总分和金额使用确认快照，工资不重复计入绩效基础项。

### 3.3 项目经营

- 项目台账、施工段、工序库、合同清单与项目成员。
- 工程量日报定价预览、无价草稿、工程量确认、日报附件、签证变更及签证附件。
- 班组、班组单价、班组结算与支付记录。
- 项目回款、成本、机械台班、材料辅材、资料归档、风险预警和项目经营看板。

### 3.4 微信小程序现场端

- 微信登录与账号绑定。
- 首页工作入口、本人工资、工资详情及确认/异议。
- “现场”页签、工程量日报和签证的分页查询、服务端详情编辑与附件上传。
- 角色化统一待办、完整审批详情和个人中心。

## 4. 本次不纳入的事项

### 4.1 明确不在范围

- 部署与运维基础设施，以及真实生产账号、证书、密钥和对象存储开通。
- 与银行、税务、社保或外部财务系统的直接对接及自动扣缴。
- 通用 OA、复杂可配置审批流、完整财务总账或替代专业财务系统的能力。
- 多租户隔离、跨公司结算和未在现有代码中实现的外部开放平台。

### 4.2 后续版本方向，不作为本次上线承诺

- 移动消息通知、工资发放和审批提醒、日报或签证逾期提醒。
- 多项目经营排行、项目风险评分、班组成本排行、签证回收率与奖金效果分析。
- 员工、工资、工程量的批量导入及新增经营报表导出能力。

这些方向来自 `docs/ROADMAP.md` 的 v3.1、v4.0 和 v4.1，不得在本次 UAT 中作为
必测或验收通过条件。

## 5. 上线前必须完成的非部署条件

本范围只在下列条件得到证据后，才能进入 `G3` 非部署正式上线就绪审查：

1. `docs/LOOPMAP2.md` 中 P20-P27 的必需 loop 已完成，或有正式记录的延期批准。
2. 工资、项目、签证、班组结算、薪酬来源和小程序关键路径已按 UAT 清单通过验证。
3. 匿名、授权、越权及敏感信息查看的权限回归通过，私有附件不能被未授权访问。
4. 空库迁移和历史数据升级有可复现验证记录；核心历史数据未丢失。
5. Web 和小程序的关键页面已完成正常、加载、失败、空状态和窄屏或真机体验验收。
6. 未关闭的 P0/P1 缺陷为零；其余延期项已写入缺陷策略与 UAT 记录。

### 5.1 当前明确的 Gate 阻断项

截至 2026-07-13，真实小程序账号登录、日报和签证上传、待办审批、工资确认、弱网恢复，
以及对应截图或录屏尚未形成非生产环境验收证据。该事项由 `L2-27-02` 负责，不得因
`L2-25-02` 的工程与未登录模拟器检查通过而视为通过。

在 `L2-27-02` 中，这些场景必须完成并留存脱敏证据，或者通过本文件第 6 节的范围变更
规则和 [`LAUNCH_DEFECT_POLICY.md`](LAUNCH_DEFECT_POLICY.md) 取得书面延期批准。两者均未
完成时，`G3` 必须给出“不批准”结论。

## 6. 范围变更规则

- 新功能、删减功能或延期功能必须同时更新本文件、对应 UAT 用例和
  `docs/LOOPMAP2.md` 的影响记录。
- 不得把“代码存在”写成“已验收”；未完成验证的功能仍受本文件第 5 节约束。
- 涉及工资、项目结算、权限、文件访问、迁移或敏感字段的范围变更，必须增加正向和
  越权/失败验证，并在上线 Gate 中重新审查。
