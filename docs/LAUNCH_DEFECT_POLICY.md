# LaborFlow 正式上线缺陷治理与延期策略

## 1. 目的与适用范围

本策略用于非部署正式上线 Gate 前的缺陷记录、分级、阻断、复测和延期批准。它适用于
Web、服务端、小程序、权限、文件、工资、项目结算、迁移和文档验收。它不替代生产部署、
监控、备份、密钥或基础设施流程。

产品范围与 Gate 条件以 [`LAUNCH_SCOPE.md`](LAUNCH_SCOPE.md) 为准；业务场景以
[`UAT_CHECKLIST.md`](UAT_CHECKLIST.md) 为准；高风险变更的证据规则以
[`REGRESSION_EVIDENCE_POLICY.md`](REGRESSION_EVIDENCE_POLICY.md) 为准。

每个问题必须使用测试或脱敏数据记录，至少包含：编号、发现日期、发现人、环境/版本、
角色、场景或 UAT 编号、数据夹具标识、复现步骤、预期、实际、影响范围、等级、负责人、
修复提交或证据、复测结果和 Gate 结论。不得记录密码、token、openid、真实个人信息、
真实工资或生产附件。

## 2. 缺陷等级与处理时限

| 等级 | 定义与示例 | Gate 处理 | 最低闭环要求 |
| --- | --- | --- | --- |
| P0 | 登录或权限绕过；敏感数据/私有附件泄露；工资金额、已发放状态、项目结算或确认收入错误且可能造成重大错误；数据损坏或无法恢复 | 立即阻断 UAT 和上线审查；不得豁免 | 修复、受影响数据核查与纠正、正向和越权/失败复测、审计证据、Gate 复审 |
| P1 | 关键主流程不可完成或结果不可信；合法角色被错误拒绝；状态机、附件归属、迁移或关键审计失效；核心页面持续不可用 | 阻断上线；不能以一般“后续优化”延期 | 修复并复测，或先从正式范围移除受影响能力并完成书面范围变更、风险评估和 Gate 重审 |
| P2 | 不改变数据正确性、权限或关键状态机的体验、文案、布局、非关键性能或边缘流程问题 | 可在受控条件下延期 | 记录影响、临时处置、负责人、计划日期、复测入口和书面批准；Gate 明确列为已知延期 |

分级不确定时按较高等级处理，直到 Gate 负责人和业务负责人给出书面结论。任何看似 P2
但影响工资金额、项目金额、授权范围、附件私密性、登录或迁移的数据问题，都应升级为
P0/P1 候选。

## 3. 缺陷处理流程

1. 发现人停止可能扩大影响的操作，保存脱敏的复现步骤与证据，并创建问题记录。
2. 负责人在记录中确认等级、影响范围、临时处置和修复责任；涉及权限、金额、附件或
   数据迁移时同时通知 Gate 负责人。
3. 修复必须关联提交、测试结果和受影响角色；高风险变更遵守回归证据策略。
4. 独立于修复者的执行者使用相同角色、夹具和场景复测，更新为 `pass`、`fail` 或
   `blocked`，而非只写“已修复”。
5. Gate 负责人在 UAT 签字和正式就绪审查中确认问题状态；P0/P1 未关闭时结论只能是
   “不批准”。

## 4. 阻断与延期批准

P0 不允许延期批准。P1 不能通过“风险接受”直接带病上线；只有将该能力从当前正式范围
移除并完成范围变更后，才能以新的范围重新审查。P2 可延期，但批准不是关闭缺陷，必须
保留为可追踪的已知延期。

延期批准必须由业务负责人和 Gate 负责人书面确认，并包含：

1. 问题编号、等级、受影响角色和 UAT/Gate 条目。
2. 不纳入当前范围的功能或场景、用户影响和临时操作说明。
3. 不影响工资金额、资金状态、项目金额、权限、附件私密性、登录安全和数据完整性的
   具体依据；不能证明时不得延期。
4. 风险责任人、修复负责人、目标日期、复测方式和撤销批准条件。
5. 对 `LAUNCH_SCOPE.md`、`UAT_CHECKLIST.md`、问题跟踪和最终 Gate 的同步更新。

没有以上字段的聊天结论、口头同意或“后续再测”都不是有效延期批准。

## 5. 当前已知 Gate 项

依据 2026-07-13 的明确指示，真实小程序账号登录、日报与签证上传、待办审批、工资确认、
弱网恢复以及对应截图/录屏，尚未有非生产环境的完整人工证据。它们是
当前正式上线审查的 Gate 阻断项，不是已通过结论，也不应默认作为 P2 延期。

上线审查前必须完成这些真实流程并留存脱敏证据，或按本策略与
[`LAUNCH_SCOPE.md`](LAUNCH_SCOPE.md) 完成书面范围延期批准。此前的最终结论必须是
“不批准上线”。

## 6. Gate 判定规则

- 只有所有必需 UAT、测试和证据通过，所有 P0/P1 为零，且每一项 P2 已有有效延期批准时，
  才能给出“批准进入部署阶段”的非部署结论。
- 任一必需场景未执行、证据缺失、P0/P1 未关闭、延期批准缺字段，或远端质量门禁未按要求
  启用时，结论为“暂不批准”，并记录下一步和责任人。
- “暂不批准”是如实的 Gate 结果，不回滚已验收的业务数据，也不等同于将问题关闭。
