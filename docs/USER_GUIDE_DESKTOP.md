# LaborFlow 桌面管理端操作手册

## 1. 用途与使用边界

本手册说明当前范围内五类角色在桌面管理端的日常操作路径。它只描述已经存在的页面和
角色边界，不增加功能承诺。正式范围、延期事项和上线条件以
[`LAUNCH_SCOPE.md`](LAUNCH_SCOPE.md) 为准；精确菜单、接口和数据范围以
[`ROLE_PERMISSION_MATRIX.md`](ROLE_PERMISSION_MATRIX.md) 与服务端授权为准。

使用前应由管理员创建非生产测试账号、分配角色并完成员工绑定。不要在本手册、截图、
导出文件或缺陷记录中保存密码、token、身份证、银行卡、手机号或真实工资数据。

所有用户从登录后进入“工作台”。界面只显示当前角色可访问的菜单；菜单不存在或直接访问
受限地址被拒绝，都属于预期的权限行为。遇到 401、403、加载失败或数据异常时，不要反复
提交写入操作：记录时间、页面、角色和测试数据标识，再按
[`LAUNCH_DEFECT_POLICY.md`](LAUNCH_DEFECT_POLICY.md) 处理。

## 2. 角色路径速览

| 角色 | 主要菜单 | 典型完成结果 | 不应执行的操作 |
| --- | --- | --- | --- |
| ADMIN | 工作台、组织、工资、项目、薪酬与绩效、系统 | 账号与角色、微信绑定、操作日志可追溯 | 使用他人账号代替业务角色验收 |
| BOSS | 工作台、组织、工资、项目、薪酬与绩效 | 审核工资，查看经营与薪酬数据 | 系统用户、角色、微信绑定和操作日志管理 |
| FINANCE | 工作台、工资、项目财务、薪酬与绩效 | 维护工资、发放、导出及项目财务数据 | 审核月度工资；编辑、提交或确认他人日报和签证 |
| MANAGER | 工作台、组织、项目、项目财务、薪酬与绩效 | 维护项目资料，确认日报和签证，处理结算 | 工资管理菜单与工资全量接口 |
| EMPLOYEE | 不使用桌面管理端办理现场业务 | 使用小程序查看本人信息、填报日报/签证 | 组织、工资、项目、薪酬和系统管理 |

角色可以同时拥有多个角色标识时，以后台分配的实际权限集合为准。验收时仍应使用单一
角色测试账号验证最小权限，而不是以高权限账号覆盖全部流程。

## 3. ADMIN：账号、组织与审计

1. 在“系统 > 用户”创建或维护测试用户；停用前确认该账号不再承担未完成的验收步骤。
2. 在“系统 > 角色”核对 `ADMIN`、`BOSS`、`FINANCE`、`MANAGER` 和员工角色分配；再使用
   对应账号重新登录，确认菜单按预期变化。
3. 在“系统 > 微信绑定”维护账号与员工的绑定关系。需要验证小程序工资时，先确保员工
   处于有效状态且绑定关系正确。
4. 在“员工信息”维护员工、部门和岗位；涉及工资或项目的测试数据要标识为非生产夹具。
5. 在“系统 > 操作日志”按时间、操作者和业务编号抽查关键操作。工资创建/审核/发放、
   日报和签证确认、用户与微信绑定变化都应能追溯；还可按模块、动作、结果和业务 ID
   组合筛选。

完成标准：用最低权限账号重新验证管理员专属入口被拒绝，且日志记录与业务操作对应。

## 4. BOSS：工资审核与经营查看

1. 在“工资管理 > 月度工资”打开待审核月份，核对员工、工资项、来源和金额后选择通过或
   驳回；意见应与状态变化一起保留。
2. 在“工资统计”和“异常提醒”查看汇总与待处理异常，必要时回到月度工资定位明细。
3. 在“项目经营 > 项目经营看板、风险预警、项目回款、项目成本”查看经营数据；签证确认
   后应能从项目看板或财务信息复核确认收入。
4. 在“工程量日报、工程量确认、签证变更、班组结算”复核项目管理链路，按职责确认或
   记录异常。

完成标准：审核结果不可由 FINANCE 账号替代；BOSS 账号没有系统管理入口。

## 5. FINANCE：工资发放与项目财务

1. 在“工资项”和“工资档案”维护工资规则及员工档案，再在“月度工资”创建、生成、调整
   并提交测试月份。
2. 审核通过后，在同一工资月份登记单人或批量发放，并关联允许的凭证；核对发放日期、
   方式和状态。
3. 在“工资统计”和“异常提醒”复核生成和发放结果；按当前页面提供的入口完成导出前，
   确认导出数据仅用于测试且已脱敏。
4. 在“薪酬与绩效”先配置指标，再创建绩效方案；方案权重合计必须为 100 才能启用。
   按方案生成员工成绩，刷新自动指标，必要时填写原因覆盖自动分，确认后由工资生成读取
   服务端保存的绩效金额快照。
5. 在“项目经营 > 班组结算、项目回款、项目成本、风险预警、项目经营看板”处理项目
   财务数据和结算支付记录。

完成标准：FINANCE 无法审核或驳回月度工资，也不能代替项目管理人员编辑、提交或确认
他人日报、签证。

## 6. MANAGER：项目执行与确认

1. 在“员工信息、部门管理、岗位管理”维护项目所需的组织资料；在“项目成员”按项目、
   姓名、岗位或状态查询，只从有效员工中添加，维护职责、停用、重新启用或移除。
2. 在“项目经营 > 项目台账、施工段管理、工序库、合同清单、班组管理、班组单价”建立
   可用于日报和结算的测试基础数据。
3. 在“工程量日报”使用定价预览核对合同清单、时点单价和产值；多个匹配清单时明确选择，
   无价格日报只能保存草稿。在“工程量确认”确认或驳回提交记录并写清意见。
4. 在“签证变更”确认或驳回签证，并复核确认金额是否反映在项目经营数据中。
5. 在“班组结算”处理已具备条件的结算；结合“项目回款、项目成本、项目经营看板”核对
   项目财务结果。
6. 在“薪酬与绩效”维护本职责范围内的考勤、绩效和奖金资料。

完成标准：日报、签证与结算不得跳过既有状态限制；MANAGER 不应看到工资管理菜单或
读取工资全量数据。

## 7. EMPLOYEE：转至小程序现场端

员工现场业务不在桌面管理端办理。员工应使用
[`USER_GUIDE_MINIAPP.md`](USER_GUIDE_MINIAPP.md) 完成工资查询、日报、签证和个人资料操作。
员工账号若打开桌面管理端的组织、工资、项目、薪酬或系统地址，应收到拒绝提示且不产生
数据写入。

## 8. 日常异常处理

- 写入前先核对页面中的当前状态、项目归属、员工归属和金额；不要用浏览器刷新或重复点击
  来规避状态限制。
- 被驳回的日报或签证按意见修改后再提交；没有权限时联系管理员调整角色或项目成员关系，
  不使用共享账号。
- 发现金额错误、越权访问、私有附件泄露、登录绕过或已发放状态异常，立即停止相关流程，
  按 P0/P1 候选记录并通知 Gate 负责人。
- 其他页面、网络、空状态或交互问题按缺陷策略记录；只有完成复测或获得符合策略的批准，
  才能在 UAT 中关闭。

对应 UAT 用例、所需证据与角色验收清单见 [`UAT_CHECKLIST.md`](UAT_CHECKLIST.md)。
