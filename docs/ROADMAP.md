# ROADMAP.md

# 建筑劳务经营与薪酬管理平台版本路线图

## 1. 说明

本文记录从 v0.1 到 v3.0 的版本设计与后续方向。它保留版本需求的来源，不能替代
当前正式上线的范围定义。

当前交付状态：

```text
v0.1：员工与工资管理，已进入当前代码范围
v0.2：工资导出、工资条、异常提醒与历史查询，已进入当前代码范围
v1.0：项目经营核心流程，已进入当前代码范围
v1.1：项目回款、成本、资料、风险预警，已进入当前代码范围
v2.0：考勤、绩效、项目奖金与工资联动，已进入当前代码范围
v3.0：微信小程序现场端，已进入当前代码范围
```

“已进入当前代码范围”不等同于已通过正式上线验收。当前发布范围、明确延期项和
验收关卡以 [`LAUNCH_SCOPE.md`](LAUNCH_SCOPE.md) 与
[`LOOPMAP2.md`](LOOPMAP2.md) 为准。

面向当前版本的操作路径与上线治理分别见
[`USER_GUIDE_WEB.md`](USER_GUIDE_WEB.md)、[`USER_GUIDE_MINIAPP.md`](USER_GUIDE_MINIAPP.md)
和 [`LAUNCH_DEFECT_POLICY.md`](LAUNCH_DEFECT_POLICY.md)。历史版本规划不构成额外功能
承诺，也不能替代 UAT 结果或最终 Gate 决策。

平台整体方向：

```text
v0.1：员工信息管理 + 员工工资管理
v0.2：工资管理增强
v1.0：项目经营管理
v1.1：项目经营增强
v2.0：薪酬与绩效管理
v3.0：微信小程序端
```

所有后续版本继续沿用 `PROJECT_BRIEF.md` 中的技术约定：

```text
Web：React 19 + React Router + TypeScript + Tailwind CSS + shadcn/ui
服务端：Spring Boot 3 + Java 21 + MyBatis Plus + Spring Security + JWT
数据库：PostgreSQL 18
主键：MyBatis Plus 雪花算法 Long ID，IdType.ASSIGN_ID
```

# 2. v0.2：工资管理增强（版本设计基线）

## 2.1 版本目标

v0.2 在 v0.1 的员工信息和工资台账基础上，增强工资管理的可用性、可追溯性和导出能力。

目标：

```text
让财务能够更方便地做工资表、查历史、导出工资数据、发现工资异常。
```

---

## 2.2 功能范围

### 1. 工资表导出

支持：

```text
月度工资表导出 Excel
员工工资明细导出 Excel
部门工资汇总导出 Excel
工资发放记录导出 Excel
```

导出字段至少包括：

```text
工资月份
员工姓名
部门
岗位
应发金额
扣减金额
实发金额
发放状态
发放日期
发放方式
备注
```

---

### 2. 工资条导出

支持按员工生成工资条。

工资条内容：

```text
员工姓名
工资月份
应发项明细
扣减项明细
应发金额
扣减金额
实发金额
发放日期
备注
```

第一版可以只支持 Excel 导出，暂不做 PDF。

---

### 3. 员工历史工资查询增强

在员工详情页增加：

```text
历史工资列表
年度工资汇总
月度工资趋势
累计实发金额
最近一次发放记录
```

---

### 4. 工资异常提醒

识别以下异常：

```text
银行卡号为空
实发工资为 0
实发工资小于 0
工资较上月波动超过设定比例
已审核但未发放
已发放但无凭证
重复创建同月份工资表
```

异常只做提醒，不强制阻断业务。

---

### 5. 操作日志增强

工资相关操作必须记录：

```text
创建工资表
修改工资明细
提交审核
审核通过
审核驳回
单人发放
批量发放
上传凭证
归档工资表
导出工资表
```

---

## 2.3 新增或调整页面

```text
/salary/monthly/:id/export
/salary/monthly/:id/payslip
/employees/:id/salary-history
/statistics/salary/anomalies
```

---

## 2.4 验收标准

```text
1. 可以导出月度工资表。
2. 可以导出员工工资条。
3. 可以查看员工历史工资。
4. 可以查看工资异常提醒。
5. 工资导出不会改变业务数据。
6. 所有关键操作都写入操作日志。
```

# 3. v1.0：项目经营管理（版本设计基线）

## 3.1 版本目标

v1.0 开始建设建筑劳务公司的项目经营模块。

重点不是做通用项目管理，而是围绕市政电缆线隧道工程的真实经营问题：

```text
工程量做了多少？
班组该结多少钱？
签证有没有留痕？
项目当前赚不赚钱？
```

---

## 3.2 核心业务对象

```text
项目
施工段
工序
工程量日报
工程量确认
班组
班组单价
班组结算
签证变更
项目成本
项目经营看板
```

---

## 3.3 功能范围

### 1. 项目台账

字段：

```text
项目名称
甲方/总包
合同金额
合同开始日期
合同结束日期
项目经理
项目地址
施工范围
项目状态
备注
```

项目状态：

```text
not_started：未开工
in_progress：施工中
paused：暂停
completed：已完工
settled：已结算
```

---

### 2. 施工段管理

适配市政电缆线隧道工程。

结构：

```text
项目
  ↓
标段，可选
  ↓
施工段
  ↓
井号/桩号
  ↓
工序
```

施工段字段：

```text
项目ID
施工段名称
起始桩号
结束桩号
起始井号
结束井号
长度
备注
```

---

### 3. 工序库

内置常用工序：

```text
测量放线
沟槽开挖
基底处理
垫层施工
底板钢筋
底板模板
底板混凝土
侧墙钢筋
侧墙模板
侧墙混凝土
顶板施工
防水施工
回填
支架安装
接地施工
防火封堵
清理验收
```

支持新增、编辑、停用工序。

---

### 4. 工程量日报

现场每日填报：

```text
施工日期
项目
施工段
工序
完成工程量
单位
施工班组
施工人数
机械使用
现场照片
异常说明
填报人
状态
```

日报状态：

```text
draft：草稿
submitted：已提交
confirmed：已确认
rejected：已驳回
```

---

### 5. 工程量确认

流程：

```text
现场填报
  ↓
项目经理确认
  ↓
商务/结算员审核
  ↓
进入班组结算和项目产值
```

规则：

```text
未确认工程量不能进入班组结算。
已确认工程量可以进入班组结算。
已确认工程量可以参与项目产值计算。
```

---

### 6. 班组管理

班组字段：

```text
班组名称
班组负责人
联系电话
工种类型
结算方式
状态
备注
```

班组和员工分开管理。

员工工资属于薪酬模块，班组结算属于项目经营模块。

---

### 7. 班组单价

支持按项目、班组、工序设置单价。

字段：

```text
项目ID
班组ID
工序ID
单位
单价
生效日期
状态
```

---

### 8. 班组结算

根据已确认工程量生成班组结算。

计算公式：

```text
班组应结金额 = 已确认工程量 × 班组单价 + 零星补偿 - 扣款
```

结算字段：

```text
项目ID
班组ID
结算月份
确认工程量
结算金额
扣款金额
实付金额
结算状态
付款状态
备注
```

---

### 9. 签证变更

用于记录额外工程量和现场证据。

签证类型：

```text
设计变更
工程量增加
障碍物处理
管线迁改配合
返工
停工窝工
夜间施工
临时排水
二次倒运
零星用工
其他
```

签证字段：

```text
项目ID
施工段ID
发生日期
签证类型
事件原因
责任方
增加工程量
预计金额
人工数量
机械台班
材料说明
照片附件
状态
```

状态：

```text
draft：草稿
submitted：已提交
confirmed：已确认
rejected：已驳回
```

---

### 10. 项目经营看板

核心指标：

```text
合同金额
已完成产值
已确认工程量
班组应付金额
其他成本
当前毛利
签证待确认金额
项目回款金额，预留
项目风险
```

第一版项目经营看板只做基础统计，不做复杂预测。

---

```text

查看回款进度
```

核心字段：

```text
项目ID
回款日期
回款金额
付款单位
凭证附件
备注
```

```text
材料到货记录
材料使用记录
材料费用归集
材料影响施工记录
```

重点记录：

```text
材料不到导致停工

辅材超耗
```

---

### 5. 资料照片归档

按项目、施工段、工序归档：

```text
项目
施工段
工序
日期
资料类型
附件
上传人
```

资料类型：

```text
现场照片
签证资料
隐蔽工程照片
验收资料
安全整改
其他
```

---

### 6. 项目风险预警

预警类型：


# 5. v2.0：薪酬与绩效管理（版本设计基线）

## 5.1 版本目标

v2.0 将 v0.1 的工资管理升级为完整的薪酬与绩效管理。

目标：

```text
把员工工资、项目奖金、绩效评分、项目经营结果打通。
```

---

## 5.2 功能范围

### 1. 考勤管理

第一版做轻量考勤，不做复杂定位打卡。

功能：

```text
月度出勤天数
请假天数
加班天数
缺勤天数
外勤天数
项目驻场天数
```

支持手工录入和 Excel 导入。

---

### 2. 绩效指标管理

按岗位配置指标。

项目经理指标示例：

```text
项目毛利率
工期达成率
回款达成率
签证确认率
安全质量扣分
```

施工员指标示例：

```text
日报及时率
工程量准确率
现场照片完整率
整改闭环率
```

商务/资料员指标示例：

```text
签证提交及时率
签证确认金额
计量资料完整率
结算资料归档率
```

财务指标示例：

```text
工资发放准确率
付款审核及时率
回款跟进完成率
```

---

### 3. 绩效评分

支持：

```text
按月评分
按项目评分
按岗位评分
手动评分
系统自动带出部分项目指标
绩效结果确认
```

---

### 4. 项目奖金池

奖金池计算方式：

```text
项目奖金池 = 项目最终毛利 × 奖金比例
```

支持设置：

```text
项目ID
奖金比例
奖金池金额
发放条件
发放状态
```

发放条件示例：

```text
项目毛利率达到目标
项目回款达到目标
无重大安全质量事故
签证资料完整
```

---

### 5. 奖金分配

支持按岗位比例分配：

```text
项目经理
施工负责人
商务/资料
财务
其他支持人员
```

奖金进入工资表：

```text
绩效奖金
项目奖金
专项奖励
```

---

### 6. 工资表升级

v0.1 的工资表增加来源字段：

```text
固定工资
考勤扣款
绩效工资
项目奖金
手工调整
其他扣款
```

工资表生成逻辑升级为：

```text
实发工资 = 固定工资 + 补贴 + 绩效工资 + 项目奖金 - 考勤扣款 - 其他扣款
```

# 9. 版本边界原则

```text
1. v0.1 和 v0.2 只关注员工信息与工资管理。
2. 班组结算必须放在项目经营模块，不进入员工工资模块。
3. 项目经营模块不替代完整财务软件，只做项目经营账。
4. 薪酬绩效模块基于工资和项目经营数据扩展，不重新做一套工资表。
5. 小程序端不重复造业务逻辑，只调用服务端 API。
6. 每个版本必须能独立交付和验收。
```
